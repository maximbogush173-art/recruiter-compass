# Компас рекрутера

Агент-помощник рекрутера поверх платформы **Поток**. Собирает разрозненные сведения
о вакансии и кандидатах в проверяемую картину, показывает, чего не хватает, предлагает
следующий шаг и готовит черновики (критерии, вопросы, отказы, слоты, соседняя вакансия).
Кадровое решение всегда остаётся за человеком.

- **Что это не является:** скорер резюме, чат-бот для кандидатов, автономный наём,
  аналитическая панель.
- **Статус:** конкурсный прототип. Демо работает на вымышленных данных (`demo-data/`).

## Запуск агента

Агент развёрнут и работает на облачном сервере. Откройте:

**http://188.225.44.97:8080**

Это рабочий интерфейс «Компас рекрутера». Напишите сообщение (например, «покажи
сводку по вакансии» или «почему кандидату отказали») — агент ответит, читая Potok
и базу состояния. Кадровых действий без вашего подтверждения агент не выполняет.

Полный путь установки и запуска с нуля — в разделе «Поднять с нуля» ниже.

## Как устроено

```
Рекрутер (React-чат) ── POST /webhook/compass-agent-lab ──► n8n
                                                                │
   Агент (AI Agent + DeepSeek) ── сам выбирает read-only инструмент ──┤
        Получить контекст вакансии / сохранённый разбор                 │
        показать вакансии / кандидатов / сводку                         │
        сформировать/подтвердить/переделать критерии                    │
        разобрать кандидатов, подготовить вопросы/слоты/сообщения       │
        разобрать расшифровку/отзыв, найти соседнюю вакансию            │
                                                                │
   Тонкие инструменты-обёртки ──► 4 блока-обработчика ──► 2 под-флоу    │
        блок 1 «Подготовка вакансии»      (нормализация резюме)         │
        блок 2 «Разбор и аутрич»          (идемпотентная запись)        │
        блок 3 «Сопровождение»                                         │
        блок 4 «Действия и отчёт» (единственный пишущий)                │
                                                                │
   Источники: Potok (данные) · Postgres (состояние/аудит) · DeepSeek (LLM)
```

- **n8n** — 24 workflow: агентное ядро, 17 инструментов (read-only + действия),
  4 блока-обработчика, 2 под-флоу. Импортируемые файлы — в `deploy/workflows/`.
- **База** — отдельный Postgres-контейнер, схема `recruiter_compass`
  (миграции в `supabase/migrations/`).
- **LLM** — DeepSeek Chat (температура 0), ключ хранится только в Credentials n8n.
- **Фронтенд** — React/Vite, статично отдаётся Caddy; тот же origin проксирует
  `/webhook/*` в n8n (CORS не нужен).

**Границы безопасности:** модель интерпретирует и выбирает **read-only** инструмент,
но не оркестрирует запись. Единственный пишущий контур — блок 4 — выполняет действие
строго по `action_id` после согласия/срока/идемпотентности и повторного чтения.
Никаких секретов в коде, промптах, workflow JSON и репозитории.

## Требования (для развёртывания)

- Сервер с Docker и Docker Compose (Linux).
- Ключ DeepSeek API.
- Bearer-токен песочницы Potok (`demo.app.potok.io`).
- База: отдельный Postgres (поднимается тем же compose).

## Поднять с нуля

### 1. Клонировать репозиторий

```bash
git clone <url> recruiter-compass
cd recruiter-compass
```

### 2. Настроить окружение

```bash
cp .env.example .env
# заполнить: COMPASS_DB_PASSWORD (пароль Postgres) и COMPASS_N8N_ENCRYPTION_KEY
# сгенерировать ключ:  openssl rand -hex 32
```

### 3. Поднять контейнеры (Postgres + n8n + Caddy)

```bash
docker compose --env-file .env -f deploy/docker-compose.yml up -d
```

- Фронтенд: `http://<IP>:8080`
- n8n-editor: только локально на сервере (`127.0.0.1:5678`, через SSH-туннель).

### 4. Применить схему и демо-данные

```bash
bash deploy/scripts/apply-migrations.sh   # схема recruiter_compass (таблицы)
bash deploy/scripts/seed-demo.sh          # демо: критерии вакансии 13 + 7 разборов
```

### 5. Создать учётные записи в n8n

Откройте редактор через SSH-туннель (`ssh -L 5678:127.0.0.1:5678 user@server` →
`http://localhost:5678`), создайте владельца и **три учётные записи с точными именами**:

| Credential (тип) | Имя | Что ввести |
|---|---|---|
| DeepSeek API (`deepSeekApi`) | `DeepSeek account` | API-ключ DeepSeek |
| Postgres (`postgres`) | `Postgres account` | host `db`, port `5432`, database `compass`, user `compass`, пароль из `.env` (COMPASS_DB_PASSWORD), SSL выкл |
| Header Auth (`httpHeaderAuth`) | `Header Auth account` | `Authorization: Bearer <токен Potok>` |

Имена важны: импортированные workflow связываются с креденшалами по имени.

### 6. Импортировать и активировать workflow

```bash
bash deploy/scripts/import-workflows.sh      # импорт 24 workflow (id сохраняются)
bash deploy/scripts/publish-workflows.sh     # активация
docker compose --env-file .env -f deploy/docker-compose.yml restart n8n
bash deploy/scripts/verify-workflows.sh
```

Откройте `http://<IP>:8080` и отправьте сообщение агенту.

## Проверка демо

Счастливый путь (кандидат Павел Андреев — полный путь до оффера; кандидат Анна
Ковалёва — team-fit veto → соседняя вакансия → слот → перенос):

1. «Сформируй критерии» → «подтверди».
2. «Разбери кандидатов» → вердикты «вести/уточнить/отклонить» с обоснованием.
3. «Подготовь вопросы/слоты/сообщение».
4. Подтверди действие → запись в Potok (только блок 4, по `action_id`).

Каждый вывод открывается до источника; агент различает «нужно выяснить» и
«не соответствует» и не оспаривает team-fit veto.

## Структура репозитория

```
src/                     фронтенд (React)
deploy/                  облачный контур: docker-compose, Caddyfile, workflow JSON,
                         скрипты (миграции/сид/импорт/активация/проверка), RUNBOOK.md
supabase/migrations/     схема recruiter_compass (0001, 0002)
supabase/seed/           демо-данные (demo-data.sql) + инструкция
demo-data/               вымышленный датасет демо (кандидаты, вакансии, ground-truth)
infra/n8n/src/           исходники блоков на n8n Workflow SDK (для чтения логики)
spec/                    контракты и правила (rule_id)
```
